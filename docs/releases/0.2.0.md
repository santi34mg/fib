# Fib 0.2.0

Fib 0.2.0 is a native compiler preview built on the reconstructed Rust workspace.
It compiles explicit single-file and build-file projects through semantic analysis,
verified SSA and LLVM 21, with installed, version-matched standard-library sources.

## Highlights

- Native scalars, structs, enums, pointers, arrays/slices, checked indexing,
  constant-initialized globals, defer and concrete generic specialization.
- Package-rooted lookup, scoped visibility and canonical cross-file linkage.
- Linux x86-64 C interoperability, function pointers/callbacks and native C linking.
- Source std allocation, formatting, string helpers, randomness, process entries,
  generic maps and Linux syscalls.
- Compiler-backed LSP diagnostics, semantic tokens, unsaved overlays and qualified-name
  completion; executable coverage for every top-level sample.

See the [changelog](../../CHANGELOG.md#020---2026-10-31) for the complete release changes.

## Install and try

The release workflow attaches `fib-0.2.0-linux-x86_64.tar.gz` and its `.sha256`
checksum after the GitHub release is published. Download both files, then:

```sh
sha256sum -c fib-0.2.0-linux-x86_64.tar.gz.sha256
tar -xzf fib-0.2.0-linux-x86_64.tar.gz
export PATH="$PWD/fib-0.2.0-linux-x86_64/bin:$PATH"
```

The archive includes `bin/fibc`, `bin/fib-lsp`, matching std sources and manifest
under `lib/fib/0.2.0/`, license, changelog and runtime dependency information.
Keep `bin` and `lib` together when moving it. Official builds use Ubuntu 24.04;
older glibc systems are not guaranteed. A compatible runtime and host `cc` are
required; Rust and LLVM development files are not required to use the bundle.
Check its `runtime-dependencies.txt` for shared-library requirements.

GitHub also supplies full tagged-source ZIP/tar.gz archives. To build from a 0.2.0
source checkout, with Rust 1.98.0, LLVM 21 development libraries and a host C
toolchain available:

```sh
cargo run --locked --no-default-features --bin fib-install -- --prefix "$HOME/.local"
fibc build --single-file samples/hello_world.fib
./samples/hello_world
```

Ensure the prefix's `bin` directory is on PATH. The installer builds release
`fibc`/`fib-lsp` binaries and installs matching std sources under `lib/fib/0.2.0`.
For development without installation, pass `--sysroot library` to `build`.
Frontend/LSP work can build without LLVM; native compilation requires LLVM.

## Migration and limits

This release contains breaking changes from 0.1.1: use prefix `[N]T`/`[]T`
containers, explicit `comp` type bindings, direct enum payloads, ordinary primitive
identifiers and `callconv "C"` in place of `extern`. String helpers live in
`std::string`; memory APIs live in `std::memory`. Character literals are uint8.
Variadics and historical positional/check/emit/release CLI flags are removed.
Install the matching std sources (compiler-declaration revision 4) with the binaries.

Default build-file discovery, recursive source discovery, general build-file
interpretation, `run`, `test`, value-returning `comp fn` execution and general tuple
lowering remain unfinished. Borrowed views do not extend backing-storage lifetimes;
ownership/lifetime enforcement is pending. External C ABI and source OS APIs
currently target Linux x86-64. The `fibc-fib` compiler experiment and public Reader
type remain scaffolding, outside the supported compiler/input feature set.

## Release handoff

Local release validation passed: both workspace test configurations, strict Clippy
in both configurations, formatting, whitespace checks and VS Code launcher tests.
The optimized installer and an installed-compiler/std hello-world smoke test passed
from outside the checkout without a sysroot override. See the
[validation record](../agents/tests/README.md) for the exact scope.

The source release includes compiler crates, editor launchers and `library/`;
the binary bundle also includes the required std sources. The workspace and sysroot versions
must remain identical. VS Code package metadata follows 0.2.0; the separate Zed
extension retains its own version.

Before publishing, review the [validation record](../agents/tests/README.md),
commit the prepared changes, and tag that reviewed commit `v0.2.0`. This preparation
does not create a tag or publish a GitHub release. Once the release is published,
`.github/workflows/release.yml` builds and tests the extracted Linux x86-64 bundle
and attaches it and its checksum. Tag/version mismatches fail before building.
Manual workflow runs and packaging-related PRs build downloadable Actions artifacts
without publishing a release. The publishing job alone has repository write access.

To build the same bundle locally with LLVM 21 and host `cc`, `tar`, `ldd` and
`sha256sum` available:

```sh
cargo run --locked --no-default-features --bin fib-dist -- --tag v0.2.0
```

Outputs go to `dist/`; `--output PATH` selects another directory. Existing archives
are never overwritten by the local packager. The workflow uses `sh` for command
steps and Rust for packaging; it does not invoke Bash or Python scripts.
